# Техническое задание: мини-дашборд «ХэндМейд Стиль» (MVP)

> **Версия документа:** 1.0  
> **Дата:** 13 октября 2026  
> **Источник данных:** `orders-sample.csv` (20 заказов за 01–10 июля 2026)  
> **Формат результата:** статичный HTML-дашборд, запускаемый двойным кликом по `index.html`

---

## 1. Цель

Заказчик формулирует задачу так:
> «Хочу дашборд, который по образцу таблицы заказов показывает общую выручку, количество заказов, топ товаров и продажи по категориям».

**Проблема.** Данные есть в CSV, но ответы на вопросы «сколько заработали», «что продаётся лучше всего» и «какая категория основная» можно получить только вручную.
**Результат MVP.** Один HTML-файл (плюс локальные JS/CSS), который при открытии в браузере показывает ответы на четыре вопроса заказчика. Без сервера, без установки.
**Критерий успеха.** Заказчик открывает дашборд и за 10 секунд называет выручку, число заказов, лучший товар и ведущую категорию.

---

## 2. Границы решения

| В MVP входит | В MVP НЕ входит |
|---|---|
| 20 строк из `orders-sample.csv` | Подключение к базе / API магазина |
| Выручка, число заказов, средний чек | Фильтры по датам и категориям |
| Топ-5 товаров по выручке | Пагинация, поиск, сортировка кликом |
| Продажи по 4 категориям с долями | Экспорт в Excel / PDF |
| Одностраничный статичный экран | Авторизация, роли, несколько пользователей |
| Понятные состояния «нет данных» / «ошибка» | Адаптив «на все устройства», дизайн-система |
| *(P1)* Динамика продаж по дням | Автоматическое обновление, история загрузок |

## 3. Данные

### 3.1. Источник и структура
`orders-sample.csv` — 20 заказов за 01–10 июля 2026, 4 категории, 8 уникальных товаров.

| Поле | Тип | Правило использования |
|---|---|---|
| `order_id` | число | Уникальный идентификатор заказа. Считать заказы по нему |
| `date` | `ГГГГ-ММ-ДД` | Группировка по дням (P1), определение периода в шапке |
| `product` | строка | Ключ группировки топа товаров |
| `category` | строка | Ключ группировки по категориям |
| `quantity` | число | Количество единиц, **не** количество заказов |
| `price` | число | Цена единицы, ₽ |
| `total` | число | Сумма заказа, ₽. **Единственный источник для выручки** |

### 3.2. Правила обработки
1. **Одна строка = один заказ.** Дедупликация по `order_id`.
2. **Проверка арифметики:** `total === quantity * price`. При расхождении — показать предупреждение, выручку считать из `total`.
3. **Неизвестная категория** → группа «Прочее».
4. **Период в шапке** вычисляется из `min(date)` и `max(date)`.

---

## 4. Метрики и формулы

| Метрика | Формула | Контрольное значение на образце |
|---|---|---|
| Общая выручка | `Σ total` | **35 050 ₽** |
| Количество заказов | `count(distinct order_id)` | **20** |
| Средний чек | `выручка / количество заказов` | **1 752,5 ₽** |
| Продано единиц | `Σ quantity` | 31 |
| Выручка товара/категории | `Σ total` с группировкой | см. п. 5 |
| Доля | `сумма группы / общая выручка × 100` | 1 знак после запятой |

**Форматирование:** рубли с разделителем тысяч (`35 050 ₽`), средний чек с одним знаком (`1 752,5 ₽`), проценты с одним знаком (`33,1 %`).

### 5.2. Блок «Топ товаров» (обязательно)
Таблица из 5 строк: `№`, `Товар`, `Кол-во, шт`, `Выручка, ₽`, `Доля, %`.
- Сортировка: выручка по убыванию.
- **Правило ничьих:** при равной выручке — по числу заказов (убыв.), затем по названию (А→Я).

### 5.3. Блок «Продажи по категориям» (обязательно)
4 горизонтальные полосы, отсортированные по выручке убывающе. Для каждой: название, сумма в ₽, доля в %. Дополнительно: число заказов и единиц.

### 5.4. Блок «Динамика по дням» (P1)
10 столбцов, по одному на дату, сумма `total` за день. Подпись даты и сумма при наведении. Реализация: `div`-столбцы с процентной высотой.

## 6. Технические требования

**Стек:** HTML + CSS + vanilla JavaScript. Без фреймворков, сборщиков, npm и обязательных CDN.
**Структура файлов:** `index.html`, `styles.css`, `data.js` (сырая CSV-строка выгрузки), `app.js`, `README.md`.
**Архитектура:** 
1. `loadOrders()` → массив нормализованных заказов.
2. `aggregate(orders)` → один объект состояния со всеми метриками.
3. `render(state)` → заполнение всех блоков из этого одного объекта.
**Ключевое требование:** все блоки считаются из **одного** агрегата. Σ категорий = Σ всех товаров = Σ по дням = 35 050 ₽.
**Совместимость:** открытие двойным кликом по `index.html` обязано работать без локального сервера (CORS не должен блокировать загрузку `data.js`).

## 7. Состояния интерфейса

| Состояние | Что показывать |
|---|---|
| Данные загружены | Штатный дашборд |
| 0 строк / пустой файл | Карточки с `0`, текст «Нет заказов за период» |
| Ошибка чтения / разбора | Баннер «Не удалось прочитать данные», вместо пустого экрана |
| Расхождение `total ≠ quantity × price` | Жёлтый баннер: число заказов с расхождением, примеры (№, дата, обе суммы), расчёт продолжается |
| Деление на ноль (0 заказов) | Средний чек = `0 ₽`, не `NaN` и не `Infinity` |
| Узкое окно (< 700 px) | Блоки складываются в одну колонку |

## 8. Критерии приёмки

- [ ] При открытии `index.html` двойным кликом отображаются все обязательные блоки.
- [ ] Выручка = **35 050 ₽**, Количество заказов = **20**, Средний чек = **1 752,5 ₽**.
- [ ] Топ-5 и категории совпадают с расчётными таблицами, отсортированы по убыванию.
- [ ] **Сходимость:** Σ категорий = Σ всех товаров = Σ по дням = 35 050 ₽.
- [ ] Сумма долей категорий = 100 % (с учётом округления).
- [ ] При замене массива данных на пустой — корректное пустое состояние, нет падения JS.
- [ ] В консоли браузера нет ошибок при штатной загрузке.

## 11. Версия 2: что реализовано

- **Фильтр по диапазону дат.** Поля «С» / «По» под шапкой ограничивают период,
  по которому пересчитываются все блоки (карточки, топ, категории, дни).
  По умолчанию — весь период выгрузки; кнопка «Сбросить» возвращает полный период.
  Даты «от» и «до» можно указывать в любом порядке — система сама приводит их
  к правильному диапазону, отбор не искажается.
- **Загрузка своего CSV кнопкой.** Кнопка «Загрузить CSV» в полосе фильтра:
  файл проверяется по тем же правилам, что и выгрузка в `data.js`
  (обязательные колонки, формат дат, числа). При ошибке показывается красный баннер
  с описанием проблемы, а текущие данные дашборда сохраняются.
  Успешная загрузка заменяет данные и сбрасывает фильтр на период нового файла.

Критерии: фильтр и загрузка пересчитывают все блоки из одного агрегата;
сходимость Σ сохраняется на любом срезе; пустой диапазон даёт состояние
«Нет данных за период»; работа ведётся офлайн на file:// без зависимостей.
